# 남성현 개인 구현 및 트러블슈팅

## 프로젝트 개요

상위 설계서를 바탕으로 STM32F4의 레지스터를 직접 제어하여 버튼과
USART2 명령으로 DC 모터의 정·역회전, 정지 및 PWM 속도 제어 기능을
구현했습니다.

개인 구현 과정에서 상위 설계서와 다르게 작성된 부분이 확인되어,
현재 코드의 동작과 향후 수정 방향을 아래와 같이 정리합니다. 이 문서는
차이점을 명확히 기록하고 이후 상위 설계와 코드의 정합성을 맞추기 위한
목적으로 작성했습니다.

## 상위 설계서와 다른 구현 사항

### 1. 모터 정지 시 GPIO 출력

- 상위 설계: PA0과 PA1을 모두 Low로 출력하여 정지
- 현재 구현: PA0과 PA1을 모두 High로 출력하여 정지
- 관련 코드: `motor.c`의 `Motor_Stop()`

현재 구현의 `Motor_Stop()`은 다음과 같이 두 출력 비트를 모두 High로
설정합니다.

```c
Macro_Write_Block(GPIOA->ODR, 0x3, 0x3, 0);
```

L293의 두 입력을 같은 레벨로 만들어 모터를 정지시키는 동작 자체는
가능하지만, 상위 설계에서 정의한 Low/Low 정지 방식과는 다릅니다.
하드웨어에서 의도한 정지 방식이 제동인지 관성 정지인지 확인한 후
상위 설계에 맞게 수정할 예정입니다.

### 2. CW/CCW의 GPIO MODER 설정값

| 상태 | 상위 설계 | 현재 구현 |
| :--- | :---: | :---: |
| `MOTOR_CW` | `0x9` | `0x6` |
| `MOTOR_CCW` | `0x6` | `0x9` |

현재 코드는 CW에서 PA0에 PWM을 출력하고 PA1을 GPIO Low로 설정하며,
CCW에서는 PA1에 PWM을 출력하고 PA0을 GPIO Low로 설정합니다. 상위
README 표의 `MODER` 값과 현재 코드의 값이 서로 반대로 작성되어
있으므로, 실제 배선과 모터 회전 방향을 다시 확인하여 설계서와 코드 중
수정할 대상을 결정할 예정입니다.

### 3. UART 속도 명령 입력 범위

- 상위 설계: 문자 `1`~`9` 입력
- 현재 구현: 문자 `0`~`9` 입력
- 관련 코드: `main.c`의 `state_handler()`

현재 구현은 `0`도 정상적인 속도 명령으로 처리합니다.

```c
else if (Uart_Data >= '0' && Uart_Data <= '9')
```

상위 설계를 기준으로 할 경우 입력 범위를 `1`~`9`로 제한하거나, `0`
단계를 사용할 필요가 있다면 상위 설계서에 해당 동작을 추가해야 합니다.

### 4. PWM 속도 단계와 Duty 범위

- 상위 설계: 9단계, Duty 50%~100%
- 현재 구현: `0`~`9`의 10단계, Duty 50%~95%
- 관련 코드: `device_driver.h`의 `MOTOR_SPEED_STEP`

```c
#define MOTOR_SPEED_INIT     50
#define MOTOR_SPEED_UP       5
#define MOTOR_SPEED_STEP(x)  ((MOTOR_SPEED_INIT) + ((MOTOR_SPEED_UP) * (x)))
```

현재 계산식에서는 `0` 입력이 50%, `1` 입력이 55%, `9` 입력이 95%가
됩니다. 따라서 상위 설계의 입력 범위와 Duty 범위를 동시에 만족하지
않습니다. 최종 속도 단계별 Duty 값을 다시 정의할 예정입니다.

### 5. USART2 수신 데이터 분류 위치

- 상위 설계: `USART2_IRQHandler()`에서 방향 명령과 속도 명령을 분류
- 현재 구현: 인터럽트에서는 수신 데이터 저장과 이벤트 발생만 수행하고,
  실제 분류는 `main.c`의 `state_handler()`에서 수행

현재 방식은 인터럽트 처리 시간을 줄인다는 장점이 있지만, 상위 설계에
기록된 모듈별 역할과 다릅니다. 기능상의 차이라기보다 책임 분리 위치의
차이이며, 팀 설계 기준에 맞춰 구조를 통일할 필요가 있습니다.

### 6. 실제 구동 상태 변수 이름

- 상위 설계: `running_state`
- 현재 구현: `applied_state`
- 관련 코드: `motor.c`

두 변수의 목적은 요청 상태인 `curr_state`와 실제 하드웨어에 적용된
상태를 비교하여 불필요한 레지스터 재설정을 방지하는 것으로 동일합니다.
현재는 이름만 다르지만 협업 시 혼동을 방지하기 위해 상위 설계의 명칭으로
통일하는 것을 검토할 예정입니다.

### 7. TIM3 동작 모드

- 상위 설계: Repeat Timer로 설명
- 현재 구현: OPM(One-pulse mode)을 설정하여 1회 만료 방식으로 사용
- 관련 코드: `timer.c`의 `Timer3_Init()`

```c
TIM3->CR1 = (1 << 4) | (1 << 3);
```

TIM3는 방향 변경 전에 1초 정지 구간을 만드는 용도이므로 현재 코드는
One-pulse 방식으로 동작합니다. 타이머를 반복형으로 사용할지 One-pulse로
사용할지 팀 설계를 다시 확인하고 문서와 구현을 일치시킬 예정입니다.

### 8. 1초 안전 지연 적용 범위

- 상위 설계: CW와 CCW 사이의 방향 전환 시 1초 정지 구간 적용
- 현재 구현: `curr_state`와 `applied_state`가 다르면 정지 상태에서 최초
  구동할 때도 1초 지연 적용
- 관련 코드: `motor.c`의 `Motor_Main()`

역방향 전환 보호라는 상위 설계의 목적보다 현재 적용 범위가 넓습니다.
최초 구동과 정지 후 재가동에도 지연이 필요한지 확인한 후 조건을
구체화할 예정입니다.

### 9. Short Press 후 PWM Duty 초기화

- 상위 설계: Short Press는 CW/CCW 방향 토글로 정의
- 현재 구현: 방향 토글과 함께 PWM Duty를 50%로 초기화
- 관련 코드: `main.c`의 `EVENT_KEY_RELEASED` 처리

```c
Motor_ProcessKeyState();
Timer5_Out_Pwm_Generator(MOTOR_SPEED_STEP(0));
```

버튼으로 방향을 바꿀 때 기존 속도를 유지해야 한다면 PWM 초기화 코드를
제거해야 합니다. 안전을 위해 속도를 낮추는 것이 목적이라면 해당 정책을
상위 설계서에 명시할 필요가 있습니다.

## 상위 설계와 동일하게 구현된 주요 기능

- PC13 EXTI를 이용한 버튼 입력
- 3초 Long Press를 이용한 모터 정지
- Short Press를 이용한 회전 방향 토글
- USART2의 `F/f`, `S/s`, `R/r` 방향 명령
- TIM3를 이용한 비동기 1초 정지 구간
- TIM5 CH1/CH2를 이용한 PWM 출력
- `curr_state`와 실제 적용 상태를 비교하는 비동기 상태 처리
- Long Press 후 버튼을 놓을 때 Short Press가 중복 실행되지 않도록 처리

## 향후 수정 계획

1. 실제 L293 배선과 CW/CCW 방향을 확인합니다.
2. 모터 정지 출력을 상위 설계의 Low/Low 방식으로 통일할지 결정합니다.
3. UART 속도 입력 범위와 단계별 PWM Duty를 상위 설계에 맞게 수정합니다.
4. TIM3 동작 방식과 안전 지연 적용 조건을 팀 설계 기준으로 통일합니다.
5. Short Press 시 기존 PWM 속도를 유지할지 팀 정책을 확인합니다.
6. 수정 후 빌드와 실제 보드 동작을 검증하고 상위 README와 다시
   대조합니다.

## 회고

개인 판단으로 작성하여 문서와 코드 사이에 차이가 생겼습니다. 이후에는

정리하고, 구현 완료 후 상위 설계서와 항목별로 대조하여 차이를 조기에
확인하겠습니다.
